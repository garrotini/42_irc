# rfc 1459

## clients

- unique nickname
- max length: 9 chars
- check protocol grammar rules
- servers must have info about all clients: real name of host, username of client

## channels

- channel is created when first client joins it
- channel is destroyed when last client leaves it
- while channel exists, any client can reference the channel using the name of it
- channels name are strings (beginning with `&` or `#`) of lengh up to 200 chars
- requirement: first char needs to be `&` or `#`
- channel name can't contain any spaces (` `), a control G (`^G`) or a comma `,`
	- (comma `,` is used as a list item separator by the protocol
- 2 types of channels: distributed channel and ... ?
- distributed channel: known to all the servers that are connected to the server
- the first char will tell if it's a "only clients" server
- to create a new channel or join an existing one, client uses `JOIN`
- if channel doesn't exist, channel gets created and user becomes a channel operator
- if channel exists already, your request to JOIN will depend on the current mode of the channel
	- if channel is invite-only (+i), an user can only join if invited
- a user may be par of several channels at once, but a limit of 10 is recommended

### channel operators commands

- KICK - eject a client from the channel
- MODE - change the channel's mode
- INVITE - invite a client to an invite-only channel (mode +i)
- TOPIC - change the channel topic in a mode +t channel

- a channel operator is identified by the `@` symbol next to their nickname 
- (it replies to NAMES, WHO and WHOIS cmds)

## messages

- each IRC message consists of up to 3 main parts: prefix(optional), cmd and cmd parameters (up to 15)
- prefix, cmd and parameters are separated by one (or more) ASCII space chars
- presence of a prefix is indicated with a `:`, which must be first char of the message itself
- there must be no gap (whitespace) between the colon and the prefix
	- prefix is used by servers to indicate the true origin of the message
	- if prefix is missing from the message, it's assumed to have been originated from the conn from it was reeived
- clients should not use prefix when sending a message
- IRC message are always lines of chars terminated with a CR-LF (carriage returne - line feed) pair
- these message shall not exceed 512 chars in len, counting all chars including the trailing CR-LF
	- so, there are 510 chars maximum allowed for cmd and its parameters

## more on messages

- protocol messages must be extracted from the contiguous stream of octets
- current solution is to designate two chars (CR-LF) as message separators
- empty messages are silently ignored, which permits use of the sequence CR-LF between messages without extra problems
- extracted message is parsed into the components <prefix>, <cmd> and list of params matched either by <middle> or <trailing> components

### BNF representations:

```
<message>  ::= [':' <prefix> <SPACE> ] <command> <params> <crlf>
<prefix>   ::= <servername> | <nick> [ '!' <user> ] [ '@' <host> ]
<command>  ::= <letter> { <letter> } | <number> <number> <number>
<SPACE>    ::= ' ' { ' ' }
<params>   ::= <SPACE> [ ':' <trailing> | <middle> <params> ]

<middle>   ::= <Any *non-empty* sequence of octets not including SPACE
               or NUL or CR or LF, the first of which may not be ':'>
<trailing> ::= <Any, possibly *empty*, sequence of octets not including
                 NUL or CR or LF>

<crlf>     ::= CR LF
```

### Notes

- <SPACE> consists only of SPACE chars. 
	- TABULATION and other control chars are considered NON-WHITE-SPACE
- NUL chars is not special in message framing, so it's not allowed within messages
- last param may be an empty string
